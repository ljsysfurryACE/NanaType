# NanaType

虚拟主播打字机：在直播中把你打的台词以 AVG / RPG 对话框的样式逐字呈现，并以 blivechat 风格保留历史记录。

- **输入框**：所见即所得——直接在与展示框完全一致的样式里打字，顶部是富文本与特效工具栏；也可切换到标记源码编辑。
- **展示框**：透明的展示框窗口，打字机逐字揭示，支持逐字特效、停顿、翻页、震屏、立绘差分。
- **历史记录**：头像 + 名字 + 气泡的聊天列表，可随打字同步出现。
- **接入 OBS**：Spout2（Windows）或 Syphon（macOS）共享 GPU 纹理，零回读，窗口隐藏时也持续输出；也可以用透明窗口捕获。
- **联动**：VTube Studio（表情、热键、参数和口型同步，`[expr]` / `[vts]` 标记按打字位置触发）、OSC、本地 WebSocket 广播。
- **双人联机**：通过 iroh 连接另一位主播，自己与伙伴的台词或实时输入镜像分别进入独立展示窗口和 OBS 输出源，共享本次会话的主播历史记录。
- **blivechat 弹幕**：连接本机运行的 [blivechat](https://github.com/xfgryujk/blivechat)，弹幕面板里可 @ 或回复观众：@ 插入头像昵称标签，回复附带原消息引用；弹幕、醒目留言、礼物、上舰也可以混入历史记录。
- **皮肤**：内置 18 套（光环、夜色、羊皮纸、ADV 经典、RPG 窗口、香草、气泡、字幕、直播弹幕、漫画、终端、掌机像素、樱花、水墨、Echo-Live 原版、Echo-Live 玻璃、Echo-Live 气泡、Echo-Live 虚空；后四套还原 Echo-Live），可导入 / 导出 `.ntskin` 皮肤包，支持热重载。
- **多语言**：简体中文、English、日本語。

## 使用

1. 启动后输入框出现在屏幕下方，展示框与历史记录窗口为透明叠加层。
2. 在输入框里直接输入台词，按 **Enter** 发送（Shift+Enter 换行，可在设置里改为 Ctrl+Enter）。Ctrl+↑ / ↓ 调回发过的台词，Esc 隐藏。
3. 选中文字后用工具栏（或 Ctrl+B / I / U）加粗、上色、描边、注音、加动效、调节奏；不选中时，设置作用于接下来输入的文字。停顿、翻页、音效、表情等标记以细竖线显示在文字间，不占排版宽度，所以输入框与展示框的换行完全一致。
4. 工具栏的 `</>` 按钮切换到标记源码，两边编辑的是同一份台词。
5. 全局快捷键：**F8** 唤出输入框，**F9** 继续（越过停顿 / 跳过当前段）。
6. 托盘菜单可显示 / 隐藏各窗口、锁定叠加层、切换模式与皮肤、打开设置。托盘图标本身也标出状态：镜像中带粉色圆点，展示框与历史记录都隐藏时变灰，叠加层锁定时带一把小锁。

输入模式：

- **编辑后发送**：写完后发送，展示框按打字机节奏播放。
- **实时镜像**：展示框实时跟随输入，发送后台词进入历史。

### blivechat 弹幕

1. 运行 blivechat（默认 `127.0.0.1:12450`）。
2. 设置 › 联动 › blivechat 弹幕：填入开放平台身份码（或房间号），点「连接」。
3. 托盘菜单或设置里打开**弹幕面板**。它是只给主播看的普通窗口，不会进入展示框或历史的 Spout 输出。面板顶部可切换「紧凑 / 气泡」，设置中的 blivechat 区域也提供同一选项，选择会自动保存，默认使用紧凑模式。紧凑列表使用 24px 小头像与 14px 换行正文；气泡模式使用统一的中性卡片配色；两种模式均独立于皮肤，跟随应用的浅色或深色外观。向上阅读时暂停跟随，可点「回到最新」继续跟随。
4. 鼠标悬浮或键盘聚焦一条观众消息时，头部显示「回复 / @」胶囊按钮，紧凑模式使用更小的按钮，显示时不会挤动正文。**@** 在输入框光标处插入观众标签（头像 + 昵称）；**回复** 只把这条弹幕作为引用挂到下一句台词上，保留草稿和光标，不自动插入 @。对话框与历史记录会在台词上方显示「头像 · 昵称：原文」。输入框底部的回复条可以取消。
5. 设置 › 历史记录 › 弹幕：让弹幕、醒目留言、礼物、上舰与台词一起出现在历史记录里，可按类型和礼物价值筛选。所有皮肤的历史统一从内容区顶部排列；消息间距按字号控制，连续消息适度收紧，大字号保留更多留白。Halo 保留 36px 头像、独立昵称、完整气泡与引用，连续台词也保留各自头像昵称；其他皮肤保留各自字体与气泡或行内结构。新安装默认开启混入历史；已有用户保留原设置。

弹幕文字会立即出现，头像与表情在后台下载到本地缓存后原位补齐，图片加载不会挡住后续弹幕；对话框、历史记录和 Spout 输出使用相同资源。回复和 @ 只用于直播画面中的本地展示，不向 B 站发弹幕、私信或通知。三个内容框内的提及标签，以及展示框与历史记录框内的引用样式由皮肤的 `[mention]`、`[dialogue.reply]`、`[history.reply]`、`[history.chat]` 决定（见 [docs/skins.md](docs/skins.md)），标记写法是 `[at=uid name="昵称"]`（见 [docs/markup.md](docs/markup.md)）。

没有直播间时可以用模拟服务器试用，它按 blivechat 的格式循环发送弹幕：

```bash
cargo run -p nanatype-blive --example mock_blivechat
```

### 双人联机

1. 输入窗口顶部展开「双人联机」，一方点击「创建联机」，复制邀请并私下发送给另一方。
2. 另一方粘贴邀请并点击「加入」。卡片显示连接状态、对方名字、直连／中继和往返延迟；需要时可填写自定义中继 URL。
3. 「展示框」始终显示自己的内容，「联机伙伴展示框」独立显示对方的内容；两者可以分别移动、缩放和隐藏。联机卡片的「伙伴窗口」按钮可切换伙伴窗口。双方保留各自皮肤和窗口布局；实时镜像模式公开正在输入的内容，编辑后发送模式只公开已发送内容。输入框和草稿各自独立，F9、跳过和清空展示只控制自己。
4. 历史窗口在联机期间显示本次会话的主播台词，按房主确认顺序排列。联机前历史和直播间弹幕不共享。离开后恢复本机历史，隐藏伙伴窗口并停止伙伴输出；本次会话不会跨进程重启恢复。会话最多保留最近 1000 条台词，并按消息大小限制裁剪。
5. 短暂断线时保留编辑能力，发送与手动播放控制暂停；重连后补齐历史并恢复最新展示状态。主动离开会结束当前双人会话，首版不自动转移房主。

图片、贴纸、头像、引用中的头像和当前立绘以内容哈希分发并缓存，资源加载不会阻塞台词。单个资源上限 16 MiB；超限或缺失时使用占位。仅自己的台词触发本机 VTube Studio／OSC 等人物控制，对方台词不会操作自己的模型。

联机邀请包含会话访问凭据，请只交给联机伙伴。iroh 在可行时使用直连，否则经端到端加密的中继转发；直连双方会获知彼此的网络地址。默认公共中继适合开发验证，有限流且不保证可用性，正式直播前应在双方实际网络上试连，必要时配置自己的中继。

### 接入 OBS

- **Spout2**：设置 › 输出 / OBS 打开 Spout2 输出。OBS 中安装 Spout2 插件，添加 *Spout2 Capture*，选择发送端名称（默认 `NanaType Display` / `NanaType Partner` / `NanaType History`），合成模式选 *Premultiplied Alpha*。
- **分别输出**：在设置 › 输出 / OBS 分别启用「展示框」和「展示框 · 联机伙伴」，再在 OBS 添加两个来源，分别选择 `NanaType Display`（自己）和 `NanaType Partner`（对方）。尺寸、透明度和发送端名称分别设置；启用的发送端名称须互不重复。伙伴输出只在联机期间运行；联机中隐藏窗口仍会持续输出。共享历史另选 `NanaType History`。
- **窗口捕获**：*Window Capture*，捕获方式选 *Windows 10 (1903 and up)*。
- **Syphon**（macOS）：设置 › 输出 / OBS 打开 Syphon 输出。OBS 中添加 *Syphon Client*，选择发送端名称（默认 `NanaType Display` / `NanaType Partner` / `NanaType History`），合成模式选 *Premultiplied Alpha*。也可以用 *macOS Screen Capture* 捕获展示框窗口。Spout2 仅 Windows。

## 台词标记

台词以 BBCode 风格的标记保存：源码模式、快捷短语和模板都用它。完整说明见 [docs/markup.md](docs/markup.md)。

```text
[@auto=1500]大家好！[wait=400][b][color=#e86a92]今天[/color][/b]也来[wave]打字[/wave]啦～
[pause][shake amp=2]哇！[/shake][se=coin][expr=smile]
[ruby=かんじ]漢字[/ruby][sticker=cats/hello h=1.6]
```

## 皮肤

皮肤是一个含 `skin.toml` 的文件夹或 `.ntskin` 压缩包，可继承内置皮肤只写差异。格式见 [docs/skins.md](docs/skins.md)。

## 构建

需要 Rust 1.98+ 和 Windows 10 SDK（图标与版本资源）。NanaUI 与 nanalive-spout（Spout2 发送端）以固定 rev 通过 GitHub 远程仓库引用，首次构建时 cargo 会自动拉取，无需本地检出；构建 nanalive-spout 需要 git 可用（会拉取 Spout2 子模块）。

```bash
cargo run -p nanatype
```

```bash
cargo test --workspace --exclude nanatype
```

离屏渲染所有窗口的界面快照（不开桌面窗口）：

```bash
cargo run -p nanatype --example snapshots -- target/snapshots nanatype.night ja-JP
```

打包（需要 `nana-packager` 与 Inno Setup 6）：

```bash
pwsh scripts/package.ps1
```

开发辅助环境变量（仅调试构建或显式设置时生效）：

| 变量 | 作用 |
| --- | --- |
| `NANATYPE_DEBUG=<文件>` | 把窗口与输出事件追加写入该文件 |
| `NANATYPE_DEMO=1` | 启动 1.5 秒后播放示例台词（调试构建） |
| `NANATYPE_DEMO_MARKUP=<标记文本>` | 覆盖自动播放的示例台词（需 `NANATYPE_DEMO`） |
| `NANATYPE_EXIT_AFTER=<毫秒>` | 到时正常退出（用于测量启动、刷出日志） |
| `NANATYPE_OPAQUE=1` | 叠加窗口改为不透明（调试构建） |
| `NANATYPE_PERF=<JSON 文件>` | 退出时保存各原生窗口呈现／输出帧数、宿主回调耗时与可用工作计数；丢弃前 2 秒 |

渲染测量、GPU 时间戳、截图比较及限制见 [渲染优化验证记录](docs/rendering-performance.md)。

## 结构

| crate | 内容 |
| --- | --- |
| `crates/model` | 台词文档模型：文字段、注音、贴纸、标记 |
| `crates/markup` | 标记语言的解析与序列化、模板 |
| `crates/playback` | 揭示时间线、播放器状态机、实时镜像差分、队列 |
| `crates/theme` | 皮肤包：清单、继承、校验、安装与导出 |
| `crates/i18n` | Fluent 文案（zh-CN / en-US / ja-JP） |
| `crates/settings` | 设置结构、版本迁移、原子写入、窗口位置 |
| `crates/audio` | 解码、混音与按采样时刻调度 |
| `crates/bridge` | VTube Studio、OSC、WebSocket |
| `crates/blive` | blivechat 客户端：协议解析、连接与重连 |
| `crates/core` | 会话逻辑：草稿、发送、继续、队列、历史、回溯 |
| `crates/p2p` | iroh 双人联机、会话排序、重连恢复与图片传输 |
| `app` | NanaUI 宿主、窗口、视图、热键、托盘、Spout |

纯逻辑 crate 不依赖界面框架，可单独测试。
